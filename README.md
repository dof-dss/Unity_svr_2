# Maestro Unity base

This repository contains Drupal core along with contrib and shared custom modules or themes for Unity sites. It is never
deployed direct to a hosting environment and instead is used to create 'server specific' forks.

When a core or contrib update is required for Unity sites it is first performed against this repository, pushed to
Github and then each 'server instance' fork will pull from this upstream source. It is imperative that any
changes to the files within this repository are not altered directly on the server instance fork as any future pulls
could possibly overwrite those changes.

## Drupal 11 baseline

The shared Composer configuration follows the Drupal 11 Unity baseline:
PHP 8.3, Drupal 11.4, Drush 13, Maestro Shell 11 and the 11.x shared Unity
packages. Hosting configuration generated by maestro-hosting uses MariaDB
10.11; environment-specific hosting files belong in the server forks.

Existing forks must update `DB_NAMESPACE` to
`Drupal\mysql\Driver\Database\mysql` in their environment files. Shared Redis
settings isolate each site's cache and locks while keeping flood records in
the database for the Flood Control UI.

The tracked modules under `web/modules/interim` preserve Filelog and File
delete during the upgrade, matching the Unity/corp-lite interim approach.
Do not install a second Composer copy of either module. Review installed
modules and remap permissions from the removed `block_content_permissions`
module to their core equivalents before upgrading an existing site. The
unsupported `clone_nodes`, `easy_install_d10`, `migrate_absolute_links`,
`permissions_filter` and Seven dependencies have also been removed, following
Unity. CKEditor is supplied by `ckeditor_lts`.

Test database updates and configuration imports in a server fork with a
database backup before deploying. This base repository has no site database
with which to verify the upgrade.

## Structure

```
└── .circleci/ (Circle CI configuration and supporting files)
├── scripts (Drupal scripts)
├── web (Drupal public web directory)
├── .env.sample (Example environment file)
├── drushmulti.sh (Drush for multisite instances)
```
